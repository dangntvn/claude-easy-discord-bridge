# 🌉 Claude Easy Discord Bridge

*(スキル/フォルダの技術名: `claude-easy-discord-bridge`)*

[English](README.md) · [Tiếng Việt](README.vi.md) · **日本語** · [中文](README.zh.md)

**Discord上でそのままClaude Codeを操作 — スマートフォンからでも。**

[Claude Code](https://claude.com/claude-code) 用のスキルで、実行中のセッションを
そのままDiscordの会話にしてしまいます。メッセージのやり取り、進捗確認 — いつでも、
どこでも、VSCodeの前に座っている必要はありません。**複数のタスク、複数のプロジェクトを
同時に**進めても、きれいに分離されたまま混同することがありません。

</div>

---

## 📌 なぜこれが必要なのか

Claude Codeは標準では1つのターミナル/VSCodeウィンドウの中でしか動かず、そこに
座って待つか、席を外した瞬間にセッションとの接続を失ってしまいます。このスキルは
まさにその問題を解決します。

> 🔌 **特に重要な点:** 事前準備や事前設定は一切不要です。Claudeとある作業の
> 途中でチャットをしている最中に、その同じ会話の中でそのまま**「Discordに接続して」**
> とだけ打てば即座に接続できます — 今やっている作業を中断する必要も、最初から
> やり直す必要もありません。これは**このスキルだけができること**です。ほとんどの
> 他のDiscordプラグイン/ボットは、作業セッションを最初からそれら経由で開始する
> ことを要求し、すでに進行中の会話の途中にDiscordを「後付け」することはできません。

| スキルなし | Claude Easy Discord Bridgeあり |
|---|---|
| Claudeとある作業の途中でチャットをしていて、Discordを使いたければ一旦止めて最初から新しいセッションを開くしかない | 作業の途中で「Discordに接続して」と打つだけ。文脈を失わず、再起動も不要 |
| 複数セッションを並行して動かすと、どのウィンドウがどれか混乱しやすい | セッションごとに専用スレッド、名前も明確で絶対に混同しない |
| 複数プロジェクトがあると、開く場所・覚えておくことが増える | プロジェクトごとに専用チャンネル、完全に分離される |
| Claudeにさっと一言聞きたいだけなのにIDEを開き直す必要がある | Discordに直接打ち込めば、Claudeがそのスレッド内ですぐ返信 |
| Claudeの作業を見守るにはパソコンの前にいなければならない | スマートフォンからDiscord経由でリアルタイムに確認・返信できる |

## ✨ 主な機能

### 🧵 複数のタスク・複数のプロジェクトを同時進行 — それでも極めてシンプル
これがこのスキル最大の強みです。複数の異なるClaude Codeの会話を（例えば
プロジェクトAでバグ修正をしながら、プロジェクトBでレポートを書く、といった具合に）
**同時に**開くことができ、Discord上ではすべてがきちんと整理されます。

- **プロジェクト**ごとに**専用のDiscordチャンネル**として表示され、プロジェクトAの
  作業がプロジェクトBに混ざることは決してありません。
- 各チャンネル内では、実行中の**会話**ごとに**専用のスレッド**として表示され、
  今行っている作業の内容に応じて自動で名前が付きます（例:「ログインバグ修正」、
  「レポート分析」）。同時にいくつタスクを開いていても、送り先を間違える心配はなく、
  正しいスレッドに入ればそのまま該当タスクとの会話になります。
- 自分で管理したり手動で名前を付けたりする必要はありません — 「Discordに接続して」
  と言った瞬間に自動で整理されます。

### 💬 リアルタイムの双方向メッセージング
Discordのスレッドにメッセージを打ち込むと、Claude Codeがほぼ即座に受け取り返信します
— 遅いポーリングもリフレッシュも不要です。

### ✅ リアクションで明確にわかる処理状態
メッセージ処理を始めた瞬間に🤔でリアクション、完了すると✅に変わります —
Discordを見るだけでClaudeが処理中か、返信済みかがすぐわかります。

### 🔁 過去の同じスレッドに正しくResume、重複作成なし
過去と同じセッションに再接続する（同じチャットを再度開く）と、以前作成した
スレッドを自動で探し当てます。スレッドが重複して作られることは決してありません。

### 🚦 柔軟な切断
1つのセッションだけ切断することも、プロジェクト全体を切断すること（他に生きている
セッションがあれば警告付き）もできます — 常に明示的な操作であり、自動で裏で
切断される仕組みはありません。

### ⚡ 高速で、余計な依存に振り回されない
メッセージ送信はREST APIを直接使用し、Gatewayを経由しません — 受信側で問題が
起きていても、送信側が止まることは決してありません。実測に基づいた性能で、
勘に頼っていません。

## 🏆 際立った利点

- **🔌 一度インストールすればずっと使える — 作業の途中でも準備なしにすぐ接続。**
  1度だけ正しくインストールすれば、以降はいつでも — Claudeとある作業の途中で
  チャットしている最中であっても — その同じ会話の中で**「Discordに接続して」**
  と打つだけで接続できます。今やっている作業を止める必要も、最初からやり直す
  必要も、追加の設定も一切不要です。これは**このスキルだけができる**点です。
  他のDiscordプラグイン/ボットは通常、作業セッションを最初からそれら経由で
  開始することを要求し、**すでに進行中の**会話にDiscordを「後付け」することを
  サポートしていません。

- **📱 通知だけでなく、本当の意味でのリモートワークが可能。** Claude Code標準の
  スマートフォン通知機能は、Claudeが何かを必要としていることを*知らせる*だけで、
  実際に返信するには元のパソコンに戻る必要があります。このスキルを使えば、
  **スマートフォン上でそのまま返信し作業を続けられます**。まるでパソコンの前で
  コマンドを打っているかのように。

- **🗂️ 複数の作業を同時に進めても絶対に混同しない。** Claude Codeの会話ごとに
  独立したスレッドが作られ、今やっている作業の内容に応じて明確に名前が付きます
  （例:「ログインバグ修正」、「レポート作成」）。3〜4個の作業を並行して進めても
  きちんと分離され、別の作業への返信を間違える心配はありません。

- **🏢 複数プロジェクト、それぞれに専用の区画。** 複数の異なるプロジェクトに
  取り組んでいる場合、プロジェクトごとに専用のDiscordチャンネルが表示され、
  あるプロジェクトの作業が別のプロジェクトと混ざることはありません。

- **⚡ 待たされない、読み込み直しも不要な高速返信。** メッセージを打ち終えると
  Claudeがほぼ即座に受け取り、リフレッシュボタンを押したり遅いチェックループを
  待ったりする必要はありません。

- **✅ 一目でClaudeが処理中か完了したかわかる。** 送信した各メッセージには
  Claudeが処理中は🤔のアイコンが自動で付き、完了すると✅に変わります —
  「終わった?」と聞き直す必要はありません。

- **🔒 プライベートで、第三者を経由しない。** すべてのメッセージは自分のマシンと
  自分自身のDiscordの間で直接やり取りされます — 会話内容を保存したり読んだり
  できる中間サーバーは他に存在しません。

- **🧠 使うのに技術的な知識は不要。** **「Discordに接続して」**と一言打つだけで、
  あとはすべてClaudeが処理します — コマンドを実行する必要も、内部でどう
  動いているかを理解する必要もありません。

- **🔁 一度セットアップすればずっと使える。** 初期セットアップは数分で終わり、
  以降は新しい会話すべてが自動でDiscord接続の準備が整った状態になり、
  最初からやり直す必要はありません。

## ⚖️ 公式Discordプラグイン（`discord@claude-plugins-official`）との比較

Anthropicも公式のDiscordプラグイン（Bun上で動くMCPサーバー、`claude --channels`
経由で統合）を提供しています。このスキルはそれとは別の方向性を選んでおり、
よりシンプルで、multi-project/multi-sessionのニーズにより忠実です。

- **進行中の会話にDiscordをその場で後付けできる。** 実行中のセッションで
  「Discordに接続して」と打つだけで済みます — 事前にDiscordが必要になると
  わかっている必要も、作業を始める前に再起動や設定をする必要もありません。
  公式プラグイン（および他のほとんどのDiscordボット）は、チャンネル/作業
  セッションを最初からそれら経由でセットアップすることを要求します。
- **1プロジェクト↔1チャンネル、1セッション↔1スレッドを自動でマッピング。**
  公式プラグインにはこの仕組みが標準で用意されておらず、`reply_to`を手動で
  使ってスレッド管理を自前で行う必要があります。
- **送信と受信が完全に分離。** `send.js`はREST APIを直接呼び出し、受信側とは
  100%独立しています — 受信を担当するlistenerが問題を抱えていても、送信は
  決して妨げられません。公式プラグインは1つのMCPサーバーにまとめられています。
- **Bun不要、MCP不要、`--channels`フラグ不要。** 既存のNode.js >= 18と、
  スキルフォルダ内での`npm install`だけで済みます。
- **セットアップが最小限。** トークンとIDを記載した1つの`.env`ファイルだけで、
  設定用のスラッシュコマンド（`/discord:configure`、`/discord:access ...`）や
  ペアリングコードの手順は不要です。
- **実機での実測に基づいており、推測に頼っていない**（node起動 約85ms、
  Discordへの1回のREST呼び出し 約0.4〜0.66秒、`fs.watch`による新着メッセージ
  検出 約14ms）— さらに、REST呼び出しをまとめる最適化を一度試したものの
  race condition/429が発生してrevertした経緯があり、現在の設計方針は理論
  ではなく実際の検証を経たものです。
- **プロジェクトごとに紐づき、グローバル設定ではない。** 別のプロジェクトで
  使いたい場合はスキルフォルダをそのままコピーするだけで、マシン全体の
  Claude Code設定には影響しません。

## 🚀 インストール

**要件: Node.js >= 18**（`node -v`で確認）。スクリプトはDiscord REST呼び出しに
グローバルの`fetch`を使用しており、これはNode 18以降でのみ利用可能です —
Node 16以下では`fetch is not defined`エラーになります。

```bash
cd .claude/skills/claude-easy-discord-bridge
npm install
```

このスキルフォルダの直下に`.env`ファイルを作成します。

```env
DISCORD_BOT_TOKEN=...
DISCORD_SERVER_ID=...
DISCORD_CHANNEL_ID=...
ALLOWED_USER_IDS=111,222,333
```

Discordボットに必要な設定:
- 権限: 親チャンネルに対する `View Channel`、`Send Messages`、
  `Create Public Threads`、`Send Messages in Threads`。
- Discord Developer Portalで**Message Content Intent**を有効化。

> 別のプロジェクトで使いたい場合は、`.claude/skills/claude-easy-discord-bridge/`
> フォルダをそのまま該当プロジェクトの`.claude/skills/`にコピーし、`.env`を
> 再設定するだけです。

## 🎮 使い方

自分でスクリプトを実行する必要はありません — Claudeに頼むだけです。

> 「Discordに接続して」

Claudeが自動でスキルを読み込み、必要なコマンドの流れ
（`ensure-thread.js` → `listen-message.js` → `send.js` → `react.js`）を正しく
実行し、切断を指示するまで待受/返信のループを自動で繰り返します。これらの
コマンドは常にBash経由で実行されます（Windows上でも同様 — PowerShellは
使用しません。PowerShell 5.1は`node.exe`へパラメータを渡す際にアクセント付き
ベトナム語/絵文字を壊しやすいためです）。コマンドと必須ルールの詳細は
[SKILL.md](.claude/skills/claude-easy-discord-bridge/SKILL.md)を参照してください。
